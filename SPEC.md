## 1. Миссия

Сайт — **персональный портфолио-страница** Тимура Пестерева. Заменяет резюме
и работает как точка входа для:

1. Входящих запросов на AI-консалтинг и audit / fractional AI architect (основная цель).
2. Откликов на founding AI engineer / AI Lead позиции в ранних стартапах (вторичная цель).

**Не цели (строго):**

- Блог, контент-машина, лидген-воронка с автоматизацией.
- Агентство или коллективный бренд — это **персональный** сайт.
- Платформа для портфолио других людей.

## 2. Позиционирование (ADR D-001)

**Hero-формулировка (черновая, финал — в `drafts/hero.md` после adversarial review):**

> Запускаю AI-процессы, которые не разваливаются на втором месяце.

**Подзаголовок:**

> Жёсткие ТЗ перед стартом. Один AI пишет — другой проверяет. Видимая работа агентов вместо чёрного ящика.

**Ось:** spec-driven AI. Дифференциатор — рамки и проверки, а не «опыт работы с LLM».

**Биты, заимствованные из альтернативных вариантов:**

- Из варианта A («AI-архитектор для B2B-команд») — мост к **нетехническому
  founder'у** в секции «Кому подхожу». Профиль 1 не должен теряться от слова
  «spec-driven» на Hero — он должен найти себя ниже.
- Из варианта C («от vibe-coding к agentic-coding») — конкретные **метрики
  outstaff-matcher: 5 аккаунт-менеджеров → 1 менеджер + AI-сервис; время обработки
  заявки сократилось на 80% (с 4 часов до 1 часа в среднем); приглашения на
  интервью выросли на 50% (за счёт качества анализа)** — в карточке кейса и в
  supporting-числах в Hero (если уместится визуально). Плюс формулировка
  «vibe-coding → agentic-coding» как один из пяти пунктов в «Как я работаю».

**Чего избегаем:**

- ML-инженер / Data Scientist / Prompt engineer / AI evangelist / эксперт / гуру.
- «10× ускорение», «уникальная методология», «революция в AI».
- Цитаты несуществующих клиентов и кейсы, которых нет.

## 3. Целевая аудитория

Три профиля идеального читателя. Каждая секция сайта должна работать минимум
на один из них (Buyer-Impact Gate — см. §14).

**Профиль 1 — Founder / CTO B2B-стартапа, 5-50 человек.**
Хочет добавить AI в продукт или внутренние процессы. Не знает с чего начать
или начал и получил кашу. Бюджет на проект $1k-10k. Менее технический;
теряется в терминах вроде «spec-driven» — нужно подвести через простые
формулировки.

**Профиль 2 — Технический руководитель в средней компании.**
Команда инженеров есть, AI-кусок «генерит ересь». Нужен внешний взгляд,
аудит, план. Бюджет $2k-15k. Технически грамотен; принимает терминологию,
но не принимает маркетинговые клише.

**Профиль 3 — Сооснователь раннего AI-стартапа.**
Ищет founding AI engineer / AI Lead. Готов на акции + базовую зарплату.
Должен увидеть в первые 30 секунд: человек строит системы, а не пишет демо.

## 4. KPI (3 месяца после публикации)

- 5+ входящих запросов от потенциальных клиентов через любой канал сайта.
- 2+ контракта на консультации (любой формат: разовая, audit, fractional).
- Сайт в первой странице Google.ru / Yandex по 2-3 целевым запросам
  (точные запросы — задача `docs/research/seo.md`, ориентир — «AI-консультант
  B2B», «AI-архитектор», «AI-аудит для стартапа»).
- Сайт используется как материал для outbound: ссылка в Telegram-сообщениях,
  холодных письмах, LinkedIn DM.

**Контр-метрики (что НЕ считаем успехом):**

- Чистый трафик без входящих запросов — значит позиционирование не работает.
- Подписки на канал — нет канала, и не делаем.

## 5. Структура сайта (proof-first)

Одна страница, длинный скролл, без под-страниц. Порядок секций:

| # | Секция | Объём | Работает на профили | Что должно быть |
|---|---|---|---|---|
| 1 | Hero | 1-3 строки + sub + CTA | 1, 2, 3 | Позиционирование одной строкой, подзаголовок, CTA в Telegram + якорь «Кейсы ↓» |
| 2 | Кейсы | 3 карточки по ~200 слов (макс 250) | 1, 2, 3 | leadecho-leadgen, outstaff-matcher, super-agentic-ops. С реальной фактурой. |
| 3 | Как я работаю | 5 строк (по одной на принцип) | 1, 2, 3 | 5 принципов: spec перед кодом · adversarial review · артефакты в файлы · бизнес-ценность gate · vibe→agentic-coding |
| 4 | Карта компетенций | диаграмма + 3 строки | 2, 3 | Горизонтальные бары: «подхожу / расту / нужен другой специалист». Источник — §10. |
| 5 | Стек | сгруппированный список | 2, 3 | Языки, фреймворки, AI-инструменты — без рейтингов, без «всех технологий мира». |
| 6 | О тебе | 5-7 строк | 1 | Bridge для нетехнического founder'а: 5 лет IT-аутстаффа, BD-фон, pivot в AI-first. |
| 7 | Кому подхожу | 3 профиля × 2-3 строки | 1, 2, 3 | Прямо: «если ты [профиль] — пиши; если ты [не-фит] — нет». Заявляет границы. |
| 8 | Куда расту | список 2-3 направлений + дедлайны | 2 | Eval-фреймворки, observability, structured output. С самокритикой — это работает на доверие. |
| 9 | Контакты | 2-3 строки | 1, 2, 3 | Telegram (приоритет), email, одна строка про ожидание ответа. |

**Дополнительно (не секция):** SEO meta-теги, Open Graph картинка с
Hero-формулировкой, favicon, robots.txt, sitemap.xml.

## 7. Тех-стек и инфраструктура (ADR D-002)

| Слой | Решение | Причина |
|---|---|---|
| Frontend | **Astro 5** | Zero-JS by default → Lighthouse 95+ из коробки. Меньше API surface, чем Next.js — проще будущие правки руками AI-агентов. Astro Islands закрывают редкий интерактивный кусок (если понадобится). |
| Хостинг | **Vercel** | Бесплатный тариф достаточен. Native Astro adapter. Native Git-deploy после push на GitHub. |
| Контент | **MDX** | Markdown с возможностью встроить интерактив (диаграмма компетенций, например). |
| Аналитика | **Plausible** ($9/мес) или **Vercel Analytics** (free tier) | Без Google Analytics — медленнее, тяжелее. Финальный выбор — в `docs/research/analytics.md`. |
| Шрифты | **Inter** через `astro:fonts` | Локально, без CDN-зависимости. |
| Иконки | **Tabler outline** | Бесплатные, чистые, монохромные. |
| Деплой-флоу | Git push → Vercel auto-deploy с PR previews | Требуется создать GitHub-репозиторий (после approve MVP). |

**Обоснование против Next.js:** портфолио — статика без auth, форм с
backend-логикой, БД. Next.js здесь — overkill. Если в v2 понадобится
динамика (форма с rate-limit, dashboard) — мигрируем точечно или добавим
Astro server endpoint. ADR обновим тогда.

**Performance budget:**

- Lighthouse Performance ≥ 95 (desktop + mobile)
- LCP < 1.5s
- JS на первом экране < 100KB
- Полноценная мобильная вёрстка обязательна

## 8. Контент-стратегия

**Язык:** только русский. Английская версия отложена (см. §16).

**Тон:** уверенный, без свысока. Короткие предложения. Никаких длинных
структур ради SEO. Если можно сказать в 5 слов вместо 15 — говорим в 5.

**Словарь замен** (из брифа §8, обязателен к применению в drafts):

| Не говорим | Говорим |
|---|---|
| agentic systems | AI-агенты, которые работают сами |
| multi-agent orchestration | несколько AI работают вместе |
| spec-driven development | чёткое ТЗ перед началом работы |
| adversarial review | AI проверяет AI / один AI ищет ошибки другого |
| observability | видимость работы AI |
| eval frameworks | проверка качества AI |
| structured output | гарантированный формат ответа |
| LLM | AI / языковая модель |
| RAG | поиск по документам / по базе знаний |
| fine-tuning | обучение модели на ваших данных |
| trade-off | компромисс / выбор между X и Y |
| context window | объём, который AI может «удержать в голове» |
| MCP server | мост между AI и внешними системами |

В технической секции (стек, диаграмма архитектуры в кейсах) — допустимы
официальные названия инструментов на латинице.

**Гендерно-нейтрально:** «вы», должность, действие. Не «разработчик/разработчица».

## 10. Карта компетенций

**Подхожу (сильный уровень):**

- Координация нескольких AI-моделей с разными «точками зрения»

**Подхожу (средний уровень):**
- Работа с LLM-API на прикладном уровне (Claude, GPT, function calling, tool use)
- Поиск по документам с эмбеддингами, базовая работа с векторными БД

**Активно развиваю (закрою к концу лета):**
- Системная проверка качества ответов AI (метрики, регрессионные тесты)
- Видимость работы AI в реальном времени (логирование, трейсы, латентность, стоимость)
- Гарантированный формат ответа AI (валидация, повторы при ошибке)

**Не моя зона (явно обозначить):**
- Обучение и дообучение моделей с нуля
- Глубокий research в области AI
- Классическая ML-разработка (recsys, computer vision и т.п.)

**Подача на сайте:** горизонтальные бары с четырьмя цветовыми зонами
(сильный / средний / расту / не моя). Под диаграммой — три строки:

## 13. Adversarial review policy

Для значимых артефактов **обязателен** прогон через Codex CLI до commit
на main. Значимые артефакты:

- Любое изменение позиционирования
- Hero-текст
- Текст каждого кейса
- Формулировки 5 принципов в «Как я работаю»
- Карта компетенций (диаграмма + 3 строки)
- Тексты «Кому подхожу» (риск отсечь неправильных людей)

**Формат запроса к Codex:**

> «Codex, прочитай `<file>` против `SPEC.md`. Найди: маркетинговые клише, формулировки
> которые отсекают целевые профили, неподтверждённые метрики, гендерные предположения,
> английские термины из словаря замен §8. Дай список замечаний.»

Замечания Codex фиксируются в `docs/learnings.md` с датой и решением:
принято / отклонено + обоснование.

Несущественные правки (опечатки, форматирование, мелкие стилистические
правки в README) — без adversarial review.

## 14. Project laws (4)

1. **SPEC.md — источник правды.** Если код/контент расходится со SPEC —
   спецификация выигрывает. Если SPEC, по мнению агента, не прав — пишет
   `decisions/D-NNN-*.md` с обоснованием, не вносит молча правки в обход.

2. **Adversarial review обязателен** для значимых артефактов из §13.
   Самопроверка автором не считается review.

3. **Real fact > marketing claim.** Никаких выдуманных метрик. Никаких
   цитат клиентов, которых не существует. Никаких «10× ускорения». Если
   метрика предоставлена Тимуром как операционный факт (например, `outstaff-matcher`:
   4ч→1ч, −80%, +50% приглашений) — она используется с явной пометкой
   «предоставлено Тимуром, не в публичном репозитории». Невозможно подтвердить — не используем.

4. **Buyer-Impact Gate.** Каждая секция должна работать минимум на один
   из 3 целевых профилей (§3). Если секция «красивая, но никому из них не
   помогает принять решение» — режется. Декоративных секций ради
   декоративности нет.

## 18. Workflow и коммиты

**Коммиты:** после каждого логического шага. Префиксы:
`spec`, `research`, `draft`, `decision`, `milestone`, `docs`, `chore`,
`feat` (когда начнётся сборка Astro), `fix`, `refactor`. Без `wip` и `update`.

**Ветки:** прямые коммиты в `main` локально допустимы до публикации
репозитория на GitHub. После публикации — feature-ветки с PR.

**Push в `main`:** только после явного approve Тимура. Никогда force-push.

**Data-файлы** (если появятся фикстуры/скриншоты артефактов): отдельный
коммит с префиксом `data:`.
