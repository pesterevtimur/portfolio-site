# D-002 — Тех-стек: Astro 5

**Статус:** accepted
**Дата:** 2026-05-19
**Затрагивает SPEC.md:** §7

## Контекст

Портфолио-сайт — это единственная статическая страница без авторизации, базы данных и сложной бизнес-логики. Основные требования: Lighthouse Performance ≥ 95, LCP < 1.5s, JS < 100KB на первом экране (SPEC §7). Сайт должен быть прост в будущих правках, в том числе силами AI-агентов. Выбор стоит между двумя современными React-экосистемными фреймворками.

## Рассмотренные варианты

1. **Next.js** — полноценный React-фреймворк с SSR, API routes, App Router. Де-факто стандарт для новых React-проектов. Сложная система сборки; бандл включает React runtime по умолчанию.

2. **Astro 5** ⭐ — мета-фреймворк с архитектурой «zero-JS by default» и Islands. Генерирует статический HTML; JavaScript добавляется только для явно интерактивных компонентов (Astro Islands). Официальный Vercel adapter. Нативная поддержка MDX.

## Решение

Выбрали вариант **Astro 5** (не Next.js).

## Обоснование

1. **Zero-JS by default → Lighthouse 95+ из коробки.** Astro генерирует чистый HTML без JavaScript bundle, если компоненты не помечены как интерактивные. Для портфолио без форм с логикой, без авторизации, без динамических виджетов — весь сайт рендерится статически. Performance budget из SPEC §7 (LCP < 1.5s, JS < 100KB) достигается без дополнительных оптимизаций, тогда как в Next.js нужно явно отключать клиентский гидрейшн.

2. **Меньше API surface → проще правки AI-агентами.** Next.js имеет несколько систем маршрутизации (App Router / Pages Router), серверные компоненты, middleware, edge runtime — сложная среда для AI-агентов, которые будут вносить точечные правки. Astro-компоненты (.astro) — прямолинейный шаблонный синтаксис: frontmatter (JS) + HTML-разметка. Это соответствует общей философии проекта: рамки и проверки вместо магии.

3. **Native Astro adapter на Vercel.** Официальный пакет `@astrojs/vercel` обеспечивает нативную интеграцию с Vercel деплоем, включая автоматическую настройку CDN, Preview deployments при push в GitHub, и совместимость с Vercel Analytics (`@vercel/analytics`).

4. **Performance budget достигается структурно, а не через оптимизации.** Astro Islands позволяют добавить интерактивный кусок (например, диаграмма компетенций) без загрузки React для всей страницы. Если в будущем понадобится тяжёлый интерактив — подключается точечно. В Next.js обратная ситуация: React runtime всегда в бандле, от него нужно «убирать».

## Последствия

- **Положительные:** меньший JavaScript-бандл по архитектурному умолчанию; Lighthouse 95+ как стартовая точка, а не цель после оптимизаций; .astro-синтаксис понятен и прямолинеен для AI-агентов; нативный деплой на Vercel без дополнительной конфигурации.
- **Отрицательные:** если v2 потребует тяжёлый SSR-интерактив с авторизацией или персональными дашбордами — потребуется миграция или добавление server endpoints. На текущем этапе MVP этой потребности нет.
- **Нейтральные:** единственная страница `/index.astro`, минимум контента в MDX-файлах — Astro идеально подходит для этой архитектуры. Если через 6+ месяцев добавятся страницы (blog, кейсы как отдельные URL) — Astro масштабируется без смены стека.
