# D-004 — Визуальное направление: Mood A (dark gradient + grid + mono)

**Статус:** accepted
**Дата:** 2026-05-19
**Затрагивает SPEC.md:** §6

## Контекст

Портфолио-сайт должен визуально отражать позиционирование B (spec-driven AI architect) и выделяться на фоне конкурентов. Анализ 9 сайтов (`docs/research/competitors.md`) показал: 7 из 9 международных persona-сайтов используют светлую палитру, системный sans-serif и спарсную плотность. Российские AI-компании — тоже преимущественно светлые. Тёмную палитру используют только nikta.ai (РФ) и simonwillison.net (международный). В ходе brainstorm-сессии 2026-05-19 были сформулированы 4 mood-варианта; финальный выбор зафиксирован в SPEC.md §6.

## Рассмотренные варианты

1. **Mood A — dark gradient + grid + mono** ⭐ — тёмная палитра (`#0a0a0f` → `#1a1a2e`), тонкая сетка 32px в Hero, Inter + монопространственные метки. Эстетический референс: vercel.com, linear.app, resend.com.

2. **Mood B — light editorial + serif** — светлый фон, serif-шрифт, редакционный стиль. Читаемо, но типично для большинства персональных сайтов; не создаёт технологического сигнала.

3. **Mood C — hard minimalism + oversize sans** — экстремальный минимализм, очень крупная типографика. Эффектно визуально, но сложнее в реализации и может ухудшить читаемость на мобильных устройствах.

4. **Mood D — artifact-driven + screenshots** — сайт строится вокруг скриншотов реальных артефактов (SPEC.md, ADR, диаграммы). Интересный подход, но как единственный mood — риск перегрузки и сложности в поддержке. Скриншоты артефактов допустимы в кейсах (SPEC §6) — это «бит из D», включённый в mood A.

## Решение

Выбрали вариант **Mood A**: dark gradient + grid + mono.

**Зафиксированная палитра (SPEC.md §6):**

| Переменная | Значение | Применение |
|---|---|---|
| `--bg-base` | `#0a0a0f` | Основной фон страницы |
| `--bg-grad-hi` | `#1a1a2e` | Радиальный градиент Hero (правый верхний угол) |
| `--grid-line` | `rgba(255,255,255,0.04)` | Тонкая сетка 32px (только в Hero) |
| `--text-primary` | `#fafafa` | Основной текст |
| `--text-secondary` | `#9090a8` | Вторичный текст, описания |
| `--text-mono-label` | `#8a8aa0` | Моно-метки, технические подписи |

**Типографика:**
- Основной шрифт: **Inter** через `astro:fonts` (локально, без CDN-зависимости)
- Моно-метки: `ui-monospace, 'SF Mono', Menlo`

**Иконки:** Tabler outline, 16-18px, монохромные.

**Акцент:** белый CTA на чёрном фоне; граница `#2a2a3a` для secondary CTA. Без неоновых акцентов.

## Обоснование

1. **Самый «продуктовый» вид из четырёх вариантов.** Mood A визуально сигнализирует: «строим системы, а не пишем эссе». Это прямое совпадение с позиционированием B. Светлые варианты (B, C) воспринимаются как editorial/writer-сайты — не тот образ.

2. **Тёмная палитра даёт контраст для портрета Тимура.** Фото (тёплое освещение, кафе, нейтральный фон) на тёмном фоне Hero создаёт естественный контраст. На светлом фоне фото «сливается» — тёмный фон превращает фотографию в точку фокуса.

3. **Тонкая сетка + моно-метки = технологический сигнал без неоновых клише.** `rgba(255,255,255,0.04)` — сетка едва заметна, создаёт текстуру без отвлечения. Моно-шрифт для технических подписей («leadecho-leadgen», версии, даты) — стандартный паттерн developer-culture. Не аляповато, не навязчиво.

4. **Эстетический референс совпадает с целевой аудиторией.** vercel.com (деплой-платформа), linear.app (трекер для технических команд), resend.com (email-инфраструктура) — сайты, которые ежедневно видят Профили 2 и 3. Mood A сигнализирует: «я из того же мира». Это создаёт доверие без слов.

## Последствия

- **Положительные:** чёткая и полная палитра зафиксирована — меньше микро-решений во время build-фазы; визуальная дифференциация на фоне типичных светлых сайтов в нише; прямая связь между визуалом и позиционированием B.
- **Отрицательные:** тёмные сайты могут снижать читаемость для части аудитории (пожилые пользователи, яркий внешний свет). Принимаем как осознанный компромисс — целевая аудитория (Профили 1-3) работает в тёмных интерфейсах (VS Code, Terminal, Linear).
- **Нейтральные:** light/dark toggle возможен в v2, но не в MVP — одна тема упрощает реализацию. Скриншоты реальных артефактов (SPEC.md, ADR, диаграммы) допустимы в кейсах — это «бит из Mood D», включённый органично.
