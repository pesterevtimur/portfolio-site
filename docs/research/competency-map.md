# Карта компетенций — визуальная подача

> Источник содержимого: SPEC §10. Здесь решаем — КАК подать.
> Ограничения: SPEC §6 (mood A: тёмный фон, сетка, моно-шрифт, без иллюстраций, без scroll-эффектов),
> SPEC §7 (performance budget: JS < 100KB, Lighthouse ≥ 95 — библиотека чартов недопустима без явного обоснования).

---

## Содержимое (из SPEC §10)

Четыре зоны:

- **Подхожу (сильный уровень)**
  — Архитектура AI-нативных процессов с нуля
  — Чёткие ТЗ и правила для AI-агентов (spec-driven подход)
  — Координация нескольких AI-моделей с разными «точками зрения»
  — Принятие решений с явными компромиссами, без перфекционизма
  — Связка B2B-продаж и AI-инструментов (outbound, лидген, мэтчинг)
  — Рефлексия и переделка системы, когда понимаю что неправильно построил

- **Подхожу (средний уровень)**
  — Работа с LLM-API на прикладном уровне (Claude, GPT, function calling, tool use)
  — Поиск по документам с эмбеддингами, базовая работа с векторными БД

- **Активно развиваю (закрою к концу лета)**
  — Системная проверка качества ответов AI (метрики, регрессионные тесты)
  — Видимость работы AI в реальном времени (логирование, трейсы, латентность, стоимость)
  — Гарантированный формат ответа AI (валидация, повторы при ошибке)

- **Не моя зона (явно обозначить)**
  — Обучение и дообучение моделей с нуля
  — Глубокий research в области AI
  — Классическая ML-разработка (recsys, computer vision и т.п.)

## Варианты визуализации

### Вариант 1 — Горизонтальные бары (4 цветовые зоны)

Каждый пункт — строка с текстом слева и цветным баром справа. Бары одной фиксированной длины (не «шкала от 0 до 100»), отличаются только цветом зоны. Зоны разделены заголовком-разделителем.

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  ── ПОДХОЖУ (СИЛЬНЫЙ) ──────────────────────────────────── ●       │
│                                                                     │
│  Архитектура AI-нативных процессов          ████████████  сильный  │
│  Чёткие ТЗ и правила для AI-агентов         ████████████  сильный  │
│  Координация нескольких AI-моделей          ████████████  сильный  │
│  Принятие решений с компромиссами           ████████████  сильный  │
│  Связка B2B-продаж и AI-инструментов        ████████████  сильный  │
│  Рефлексия и переделка системы              ████████████  сильный  │
│                                                                     │
│  ── ПОДХОЖУ (СРЕДНИЙ) ───────────────────────────────────          │
│                                                                     │
│  Работа с LLM-API (Claude, GPT, tool use)   ████████░░░░  средний  │
│  Поиск по документам, векторные БД          ████████░░░░  средний  │
│                                                                     │
│  ── АКТИВНО РАЗВИВАЮ ────────────────────────────────────          │
│                                                                     │
│  Проверка качества ответов AI               ████░░░░░░░░  расту    │
│  Видимость работы AI в реальном времени     ████░░░░░░░░  расту    │
│  Гарантированный формат ответа AI           ████░░░░░░░░  расту    │
│                                                                     │
│  ── НЕ МОЯ ЗОНА ─────────────────────────────────────────          │
│                                                                     │
│  Обучение и дообучение моделей с нуля       ░░░░░░░░░░░░  не моя   │
│  Глубокий research в области AI             ░░░░░░░░░░░░  не моя   │
│  Классическая ML (recsys, CV и т.п.)        ░░░░░░░░░░░░  не моя   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**Реализация:** нативный HTML `<div>` + CSS custom properties. Ширина бара задана статически через CSS-класс зоны, не JS. Цвета из SPEC §6 palette.

**Pros:**
- Мгновенно читается без объяснений — паттерн «бар = уровень» универсален.
- Зоны «не моя» — пустые бары работают честнее любого текста: визуально сразу очевидно.
- Нативный CSS, 0 KB JS, Lighthouse не пострадает.
- Хорошо ложится на тёмный фон: цветные полосы дают контраст без иллюстраций.
- Mobile: вертикальный стек, бар под текстом — без потери читаемости.

**Cons:**
- Риск прочитаться как «самооценка по шкале»: человек видит бар и думает «85/100». Нужна строгая типографика зоны-подписи (`сильный / средний / расту / не моя`) вместо числовых значений — бар без числа работает как цвет, не как шкала.
- 11 пунктов подряд — монотонность. Разделители заголовков зон решают, но нужно следить за ритмом.
- Пункты «сильного» уровня — 6 штук с одинаковым баром. Визуально однообразны внутри зоны. Можно добавить sub-label в моно-шрифте (например, год или проект), чтобы разбить монотонность.

### Вариант 2 — Зональная матрица (2×2 или 4 блока в сетке)

Четыре блока в CSS Grid 2×2, каждый — одна зона с заголовком и неупорядоченным списком пунктов. Цветовое кодирование через border-left или background-tint.

```
┌───────────────────────┬───────────────────────┐
│  ● СИЛЬНЫЙ            │  ◑ СРЕДНИЙ            │
│                       │                       │
│  · Архитектура AI-    │  · LLM-API            │
│    нативных процессов │  · Векторный поиск    │
│  · Чёткие ТЗ для      │                       │
│    AI-агентов         │                       │
│  · Координация AI     │                       │
│  · Решения с          │                       │
│    компромиссами      │                       │
│  · B2B + AI           │                       │
│  · Рефлексия          │                       │
├───────────────────────┼───────────────────────┤
│  ◔ РАСТУ              │  ○ НЕ МОЯ ЗОНА        │
│                       │                       │
│  · Качество AI-       │  · Обучение моделей   │
│    ответов            │  · AI research        │
│  · Observability      │  · Классический ML    │
│  · Structured output  │                       │
│                       │                       │
└───────────────────────┴───────────────────────┘
```

**Реализация:** CSS Grid `grid-template-columns: 1fr 1fr`, четыре `<article>` с цветным `border-left` или `border-top`. 0 KB JS.

**Pros:**
- Компактнее по вертикали, чем бары: все 4 зоны видны «одним взглядом».
- 2×2 — устойчивая, знакомая структура (как BCG matrix) — не требует объяснений.
- Зона «Не моя» в правом нижнем углу — позиционирование «дальний угол» нативно коммуницирует «не главное».
- Хорошо ложится на grid-эстетику mood A.

**Cons:**
- Блок «Сильный» — 6 пунктов vs «Средний» — 2 пункта: блоки разной высоты, выравнивание ломается. CSS `align-items: start` спасает, но визуально дисбаланс остаётся.
- Четыре блока одинакового визуального веса: зоны «сильный» и «не моя» не имеют иерархии — читатель не понимает сразу, какой блок приоритетнее.
- Без баров нет мгновенного «чтения уровня»: нужен цвет и типографика, чтобы зоны различались — сложнее обеспечить читаемость на тёмном фоне без неоновых цветов (которые SPEC §6 запрещает).
- Mobile: 2×2 сворачивается в 1 колонку — 4 блока стеком = длинная страница.

### Вариант 3 — Список с меткой-тегом (inline badge)

Единый список без баров: каждый пункт = строка, рядом с текстом — маленький тег-badge в моно-шрифте (`[сильный]`, `[средний]`, `[расту]`, `[не моя]`). Цвет badge'а кодирует зону. Группировка — только через пробел между группами или тонкая линия-разделитель, без визуальных блоков и баров.

```
Архитектура AI-нативных процессов        [сильный]
Чёткие ТЗ и правила для AI-агентов       [сильный]
Координация нескольких AI-моделей        [сильный]
Принятие решений с компромиссами         [сильный]
Связка B2B-продаж и AI-инструментов      [сильный]
Рефлексия и переделка системы            [сильный]

Работа с LLM-API (Claude, GPT, tool use) [средний]
Поиск по документам, векторные БД        [средний]

Проверка качества ответов AI             [расту]
Видимость работы AI в реальном времени   [расту]
Гарантированный формат ответа AI         [расту]

Обучение и дообучение моделей с нуля     [не моя]
Глубокий research в области AI           [не моя]
Классическая ML (recsys, CV и т.п.)      [не моя]
```

**Реализация:** `<ul>` с `display: flex; justify-content: space-between`, badge — `<span>` с CSS-классом зоны, border и моно-шрифт. 0 KB JS.

**Pros:**
- Самый «инженерный» вид — changelog-эстетика, близко к linear.app и resend.com (референсы SPEC §6).
- Максимально типографичен: полностью в духе моно + тёмный фон mood A.
- Нет баров — нет риска «самооценки по шкале».
- Отлично масштабируется: mobile — badge переходит под текст.

**Cons:**
- Слабая визуальная иерархия между зонами: 11 строк в один столбец — глаз не выделяет «главное». Читатель должен дойти до значения badge'а, прежде чем понять структуру.
- Зона «не моя» — 3 строки рядом с «сильным» — 6 строк визуально выглядят равнозначно, если смотреть бегло. Пользователь Профиля 2 (tech-lead) поймёт сразу, Профиль 1 (founder) — не обязательно.
- Нет мгновенного «паттерна диаграммы» — новый посетитель за 3 секунды видит список, а не карту компетенций. Риск восприятия как «просто список навыков», а не структурированная самоаттестация.

## Рекомендация

**Выбор: Вариант 1 — Горизонтальные бары** с явными заголовками зон и статическими цветными барами.

**Обоснование относительно mood A (SPEC §6):**

1. Mood A — тёмный фон `#0a0a0f`, моно-метки, без неоновых акцентов. Горизонтальный бар с цветом через `opacity` или `brightness` поверх одного базового цвета (например, `#fafafa` с разной opacity для зон) органично вписывается, не нарушает палитры и не требует ярких оттенков.

2. SPEC §6 запрещает «сложные scroll-эффекты, иллюстрации AI-роботов» и требует минимума JS. Бары — статический CSS, 0 KB JS, Lighthouse не пострадает. Альтернатива с Chart.js (радар-чарт) — +25KB minimum bundle, нарушает SPEC §7 performance budget без весомого основания, и радар требует числовых значений которых у нас нет.

3. Вариант 3 (badge-list) — эстетически близок mood A, но слабее как «карта»: посетитель за 3 секунды видит список, а не диаграмму. SPEC §5 называет секцию именно «Карта компетенций» — визуальный паттерн бара реализует это буквально без JavaScript.

4. Вариант 2 (матрица) — компактнее, но дисбаланс блоков (6 пунктов vs 2 пункта) и отсутствие иерархии внутри матрицы работают против Профиля 1 (нетехнический founder). Бары дают мгновенное чтение даже без знания контекста.

**Важная оговорка по барам:** бар должен иметь фиксированную длину, одинаковую для всех зон — не «% от 100». Разница между зонами — только цвет. Подпись зоны (`сильный / средний / расту / не моя`) обязательна. Иначе читается как самооценка «85% vs 40%», что SPEC §14 (Project Law 3: Real fact > marketing claim) прямо запрещает.

## Технические детали реализации

**Компонент:** `src/components/CompetencyMap.astro`

**Структура данных:** массив объектов в frontmatter или константе Astro-компонента:

```typescript
type CompetencyItem = {
  label: string;
  zone: 'strong' | 'medium' | 'growing' | 'outside';
};
```

**CSS-подход (нативный, без библиотек):**

```css
/* Цвета зон — через CSS custom properties из SPEC §6 palette */
.bar--strong  { background: #fafafa; opacity: 1.0; }
.bar--medium  { background: #fafafa; opacity: 0.55; }
.bar--growing { background: #9090a8; opacity: 0.7; }
.bar--outside { background: #2a2a3a; opacity: 1.0; }

/* Фиксированная длина бара — НЕ шкала */
.bar {
  width: 120px;      /* фиксировано, не 80% от контейнера */
  height: 4px;
  border-radius: 2px;
}

/* Зона-разделитель */
.zone-header {
  font-family: ui-monospace, 'SF Mono', Menlo;
  font-size: 0.7rem;
  color: #9090a8;
  letter-spacing: 0.1em;
  text-transform: uppercase;
  margin-top: 1.5rem;
  padding-bottom: 0.5rem;
  border-bottom: 1px solid #2a2a3a;
}
```

**Размер JS:** 0 KB — компонент полностью статический Astro.

**Mobile-вёрстка (375px и шире):**

- Desktop: строка = `display: flex; justify-content: space-between; align-items: center` — текст слева, бар + метка зоны справа.
- Mobile (< 640px): бар + метка переходят под текст (`flex-wrap: wrap` или `flex-direction: column`). Ширина бара фиксирована `96px` на mobile.
- Группы зон: одинаковое поведение на любом экране — заголовок зоны растягивается на всю ширину.

**Под диаграммой — три строки (из SPEC §5):**

```
Где я подхожу · Где я расту · Где нужен другой специалист
```

Рендерятся как отдельный `<p>` с `color: #9090a8` и моно-шрифтом — визуально отделены от диаграммы.

**Файл контента:** `src/content/competency.mdx` — MDX с импортом компонента `<CompetencyMap />` и данными. Либо данные прямо в компоненте как TypeScript-константа, если нет нужды в MDX для этой секции.
