# Анализ конкурентов

> Цель: понять, как себя подают близкие специалисты (AI-консультанты, fractional CTO с AI-уклоном, persona-сайты технических founders). Что работает, чего избегать, где наш зазор. Финальные выводы используются в `decisions/D-001-positioning.md` и `drafts/visual.md`.

**Примечание по РФ-сегменту:** поиск русскоязычных AI-консультантов с персональными сайтами (не агентства) дал нулевой результат — ниша практически пустая. Индивидуальные специалисты из России либо работают через FL.ru/Habr Career (без отдельного сайта), либо выходят через профили агентств. Два РФ-примера в этом анализе — компании (just-ai.com, nikta.ai), включены как референс позиционирования на русскоязычном рынке. Это само по себе зазор: персональный сайт российского AI-консультанта — редкость.

## Подробный анализ

### 1. leerob.com

**Категория:** Persona-founder / developer-writer
**Дата проверки:** 2026-05-19

**Что работает (3 пункта):**
- Предельная лаконичность: одно предложение о себе, без перечисления всего что умеет. Читатель сам идёт дальше по ссылкам.
- Честная точка зрения: «я developer and writer» — не «expert», не «guru». Доверие через скромность.
- Личный контекст (семья, музыкальные интересы) снижает дистанцию с читателем — сайт ощущается живым, не витриной.

**Что отталкивает (2-3 пункта):**
- Полное отсутствие конкретных результатов работы — нет кейсов, нет метрик. Для консалтинговой цели сайт не конвертирует.
- Навигация через разрозненные ссылки (музыка, GitHub, Vercel) создаёт ощущение личного дневника, а не профессионального портфолио.
- CTA «Reach out» без контекста — непонятно, зачем и о чём писать.

**Визуальные паттерны:**
- Палитра: нейтральная, светлая или минималистичная (конкретные hex-цвета не идентифицированы через fetch).
- Шрифт: системный/sans-serif, без декоративности.
- Плотность контента: спарсная — несколько блоков с большим пространством между ними.

**Длина текстов:**
- Hero: ~50 слов
- О себе: 2-3 абзаца, ~150 слов
- Кейсов нет

### 2. swyx.io

**Категория:** AI Engineer advisor / devtools founder / writer
**Дата проверки:** 2026-05-19

**Что работает (3 пункта):**
- Формулировка «fostering the Rise of the AI Engineer» — конкретная миссия, не просто список навыков. Сразу понятно, кому этот человек интересен.
- Реальные числа как социальное доказательство: «>10,000 subscribers», «read by millions» — не скромно, но верифицируемо.
- Многоформатная подача: статьи + видео + подкаст + проекты. Посетитель сам выбирает глубину погружения.

**Что отталкивает (2-3 пункта):**
- Плотность навигации (Home, Ideas, About, Subscribe + видео-галереи + несколько newsletters) создаёт перегруз при первом визите.
- Нет явного CTA для входящего бизнес-запроса: сайт работает на аудиторию, но не на потенциального клиента/нанимателя.
- Широкий охват (AI, devtools, Cognition, Latent Space) размывает позиционирование — неясно, на чём именно специализируется автор.

**Визуальные паттерны:**
- Палитра: нейтральная/светлая, тёмный текст.
- Шрифт: системный, читаемый.
- Плотность контента: средняя-высокая — много секций с контентом без лишних пробелов.

**Длина текстов:**
- Hero: ~80-100 слов
- Статьи: полноформатные эссе (тысячи слов)
- О себе: краткая bio + перечисление проектов

### 4. simonwillison.net

**Категория:** AI инженер / open-source builder / активный блогер
**Дата проверки:** 2026-05-19

**Что работает (3 пункта):**
- Ежедневный объём контента как социальное доказательство: если человек пишет по несколько постов в день про AI-инструменты — он живёт в этой области, а не просто «знаком с темой».
- Конкретные метрики из реальной работы (423 Firefox security bugs через Claude в апреле 2026) — это сильнее любых слов про «опыт работы с AI».
- Проекты в продакшне (Datasette, LLM CLI) как доказательство умения строить, а не только писать.

**Что отталкивает (2-3 пункта):**

- Монетизация через Sponsor ($10/мес) ломает восприятие как потенциального бизнес-партнёра или консультанта.

**Визуальные паттерны:**
- Палитра: тёмная / нейтральная — светлый текст на тёмном фоне.
- Шрифт: системный sans-serif, моно для кода.
- Плотность контента: высокая — часто несколько постов в день, много тегов и архивных ссылок.

**Длина текстов:**
- Посты: от коротких заметок до статей 2,000+ слов
- О себе: краткий раздел About
- Кейсов в классическом понимании нет — есть подробные технические посты

## Выводы для нашего сайта

### Что заимствовать

1. **Сверхкраткий hero-текст** (источник: huyenchip.com — 12 слов, mitchellh.com — 17 слов). Ни один из 9 сайтов не выиграл от многословного hero. Конкретная формулировка в одно предложение работает лучше, чем параграф об «опыте».

2. **Конкретные числовые метрики в кейсах** (источник: ben.page — «200M requests/month», nikta.ai — «−95% времени», eugeneyan.com — «422,728 слов»). Числа из реальной работы убеждают сильнее любого описания компетенций. Наш пример: «4 часа → 15 минут» из outstaff-matcher.

3. **Явный CTA с контекстом** (источник: huyenchip.com). «Reach out if you want to find a way to work together» работает лучше, чем «напиши мне» или отсутствие CTA. Нужно объяснить, кому и зачем писать.

4. **Двухчастная структура «кто я + что я строю»** (источник: ben.page, mitchellh.com). Work Experience + Projects / или Bio + Кейсы — читатель быстро находит ответы на оба вопроса без длинного текста.

5. **Тёмная палитра как визуальный дифференциатор** (источник: nikta.ai на РФ-рынке, референс в SPEC §6 — vercel.com / linear.app). На фоне типичных светлых российских сайтов-портфолио тёмный фон сигнализирует о технической культуре. Большинство международных persona-сайтов светлые — тёмный фон здесь даст контраст и в той, и в другой группе.

### Чего избегать

1. **«Эксперт» / «гуру» / «уникальная методология»** — ни один сильный сайт из выборки не использует эти слова. Доверие строится через конкретику и скромность, а не через эпитеты.

2. **Агрессивный захват лидов** (антипаттерн: just-ai.com — форма 5+ раз на странице). Для персонального сайта это ломает доверие и ощущение «живого человека за сайтом».

3. **Отсутствие кейсов при наличии бизнес-цели** (антипаттерн: leerob.com, mitchellh.com). Сайты, которые работают на аудиторию (читатели, подписчики), могут обходиться без кейсов. Сайт, цель которого — входящие запросы на консалтинг, без кейсов не конвертирует.

4. **Перегрузка навигации** (антипаттерн: swyx.io — множество под-разделов, simonwillison.net — архив с 2002). За первые 30 секунд посетитель должен понять главное. Сложная навигация уводит фокус.

5. **Позиционирование только через роль / аффилиацию** (антипаттерн: eugeneyan.com — «Member of Technical Staff at Anthropic»). Для читателя без контекста это не говорит ни о чём. Нужно позиционироваться через то, что человек делает и для кого, а не через место работы.

### Наш зазор (чего не делает никто из проанализированных)

1. **Персональный русскоязычный AI-консультант с отдельным сайтом.** Ни один из проанализированных сайтов не находится в этой нише: международные — на английском, российские AI — агентства. Сам факт существования персонального сайта с позиционированием «AI-консультант для B2B» на русском языке — уже дифференциатор.

2. **Методологическая прозрачность как ценность.** Все проанализированные сайты либо показывают результаты (метрики), либо показывают контент (статьи/книги). Никто не показывает *как именно устроена работа*: почему spec перед кодом, почему один AI проверяет другого, почему артефакты в файлах. Секция «Как я работаю» с 5 принципами — уникальный угол для потенциального клиента, который уже обжёгся на «AI-помощнике без структуры».

3. **Явное называние того, для кого подходишь и для кого нет.** Ни один из 9 сайтов не делает этого прямо. Все либо говорят со всеми сразу (компании), либо вообще не задают вопрос аудитории (persona-сайты). Секция «Кому подхожу» с явным «если ты [профиль] — пиши; если ты [не-фит] — нет» — редкая и доверие-строящая прямота.
